# Implementation Contract: Fix Bug Hunt Findings

## Architecture Overview

This feature fixes 14 confirmed bugs in the tim-loop orchestrator skill. All changes are to markdown files containing pseudocode and prompt templates — there is no executable code, no tests, no type system. The codebase uses Python-like pseudocode with `TaskCreate`, `TaskUpdate`, `SendMessage` tool calls, and `{PLACEHOLDER}` syntax for template variable substitution. Agent reference sections (below `---` dividers) are read from disk by agents at runtime and are NOT template-substituted at spawn time.

The files live under `skills/tim-loop/` (orchestrator + agent prompts) and the repo root `README.md`.

## Shared Contracts

None. All files are markdown — there are no compilable types, interfaces, or importable modules. Each partition's edits are self-contained within their file set.

## Conventions

- **Pseudocode style:** Python-like with indentation, `if`/`elif`/`else`, `for` loops, `while` loops
- **Tool calls:** `TaskCreate:`, `TaskUpdate:`, `SendMessage` — written as inline pseudocode blocks
- **Template variables:** `{PLACEHOLDER_NAME}` in spawn prompt sections (above `---`), substituted at spawn time by the orchestrator
- **Reference sections:** Below `---` dividers, read by agents from disk — raw `{PLACEHOLDER}` text here is a bug (it won't be substituted)
- **Comments:** `##` for section markers in pseudocode, `//` for inline comments
- **Status values:** `"completed"`, `"needs_human"`, `"fixing"` — string literals in pseudocode
- **Filter patterns:** `status != "X"` for single exclusion, `status not in ("X", "Y")` for multiple

**Implementation Notes:**

Each bug maps to a specific line range in SKILL.md. Apply edits in any order — they don't overlap within the file.

**BUG-1 (line ~416):** After the REFRESH_AGENTS call at line 406 and before `outer_cycle += 1` at line 416, add `failure_history_per_builder = {}`. This resets stagnation tracking so fresh builders start clean.

**BUG-3 (line ~275):** After `Read task metadata for: verdict, failure_keys, prognosis.` (line 275), add `previous_failure_keys = failure_keys`. **BUG-8 (line ~230):** Change line 230 from `for partition in partitions:` to `for partition in partitions:` with a guard: add `if partition.status == "needs_human": continue` as the first line inside the loop body. This skips partitions that have been marked as needing human intervention.

**BUG-9 (lines ~396-416):** Wrap the `elif verdict == "FAIL":` block's REFRESH_AGENTS call in `if outer_cycle < MAX_OUTER_CYCLES:`. On the last cycle, the code should fall through to the post-loop abort instead of spawning fresh agents that are immediately abandoned. The structure should be:
```
elif verdict == "FAIL":
  if prognosis == "NEEDS_HUMAN":
    ABORT(...)

  reviewer_findings_by_builder = route_findings_to_builders(reviewer_findings, partitions)

  if outer_cycle < MAX_OUTER_CYCLES:
    Tell user: "Cycle {outer_cycle}/{MAX_OUTER_CYCLES}: Review FAIL. Refreshing agents for cycle {outer_cycle + 1}..."
    REFRESH_AGENTS(...)
    failure_history_per_builder = {}   // <-- BUG-1 reset here

  outer_cycle += 1
```
When `outer_cycle == MAX_OUTER_CYCLES`, the increment makes `outer_cycle > MAX_OUTER_CYCLES`, the while condition fails, and execution falls through to the post-loop abort naturally.

**BUG-13 — RESUME (line ~493):** Change `status != "completed"` to `status not in ("completed", "needs_human")`.

**BUG-13 — REFRESH (line ~543):** The current line reads `For each partition where status != "needs_human":`. This should be `For each partition where status not in ("completed", "needs_human"):` to also skip completed partitions.

**BUG-14, BUG-15 (lines ~376-388):** Three changes to the review task:

3. After `Read task metadata for: verdict, prognosis.` (line 388), add: `reviewer_findings = task.metadata.findings`

**BUG-22 (line ~354):** Change from `publisher = partitions[0].builder_name` to:
```

```

**BUG-23 (lines ~322-323):** After `partition.status = "needs_human"` (line 322), add:
